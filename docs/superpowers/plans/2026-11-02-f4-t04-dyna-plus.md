# F4-T04 Dyna-Q+ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure whether Dyna-Q+ adapts faster than Dyna-Q when the training defender changes from ModSecurity PL1 to DEF-REF-1 halfway through EXP-H2.

**Architecture:** Extend the existing Dyna-Q model with an exploration bonus applied only to simulated backups. Add an exact training-step defender switch to the existing attacker runner, log validation ER against the current defender and cumulative real SEND queries, then align ten-seed curves at each run's switch query count. Keep EXP-H1's live sweep in the main checkout untouched.

**Tech Stack:** Python 3.11, NumPy, existing PyTorch surrogate, YAML configs, Matplotlib, Docker lab.

**Spec:** `docs/03-plan/fase-4-nelson-planning-selfplay.md` §F4-T04 and `docs/07-experimentos/catalogo.md` §EXP-H2.

## Global Constraints

- Run EXP-H2 on `train` for 200,000 real environment steps, switching after step 100,000; evaluate on `attacker-val-v1` every 10,000 steps.
- Compare Dyna-Q and Dyna-Q+ at the same 20 simulated backups per real step, with κ ∈ {0.001, 0.01} and ten seeds per method.
- Count only real SEND actions on the query axis. The switch occurs immediately after the step-100,000 validation point, before step 100,001.
- Apply κ√τ only to model backups; τ is real environment steps since the last real visit to the state-action pair. Untried actions in a visited state use a zero-reward self-loop model until observed.
- Use committed YAML configurations, clean run metadata, and English commit messages.
- EXP-H3 Prioritized Sweeping is explicitly optional in the Phase 4 plan; decide its scope after EXP-H2 is implemented and measured.

## Review Focus

- A simulated backup must never increment real query or visit clocks.
- A newly discovered state's untried actions must not be mistaken for observed transitions.
- The first post-switch training action must use DEF-REF-1, including when the switch falls mid-episode.
- Validation at the switch point must still use PL1; later validation must use DEF-REF-1.
- Recovery time must be marked undefined if the pre-switch ER target is zero, rather than reported as a meaningful zero-query recovery.
