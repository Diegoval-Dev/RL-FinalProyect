# F4-T03 Dyna-Q Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compare Q-learning, Dyna-Q with 5/20/50 simulated updates, and PPO by validation evasion rate versus cumulative real `SEND` queries against `modsec-pl1` and `DEF-REF-1`.

**Architecture:** Extend the existing tabular Q-learning agent with a one-step model of observed mutation transitions and a learned surrogate for simulated `SEND` responses. Train through the existing experiment runner so seed, checkpoint, split, and provenance rules remain intact. Record cumulative real queries and surrogate diagnostics at every validation point; a separate summary/plot command aggregates runs by method and defender.

**Tech Stack:** Python 3.11, NumPy, PyTorch surrogate from F4-T02, Gymnasium, Matplotlib, existing YAML experiment runner.

**Spec:** `docs/03-plan/fase-4-nelson-planning-selfplay.md` §F4-T03 and `docs/07-experimentos/catalogo.md` §EXP-H1.

## Global Constraints

- `n` is 0, 5, 20, or 50; `n=0` uses the EXP-D1 Q-learning parameters.
- Only real `SEND` actions increment the horizontal query counter; simulated updates never touch the environment or backend.
- Train only on `train`, select on `val`, and do not use `test` for model fitting or hyperparameter selection.
- Seeds, budgets, and hyperparameters live in YAML; each reported number names a run ID and commit.
- Track surrogate accuracy and response-class counts with every curve; do not interpret majority-class accuracy as useful discrimination.
- Commit messages are in English, per Nelson's instruction.

## Review Focus

- Simulated `SEND` must use the pre-action ngram observation and only public response labels.
- Model updates must not count as real queries or mutate the environment.
- Evaluation calls must not change Q values, surrogate weights, or query counts.
- `n=0` must reproduce Q-learning updates with the same parameters.
- Checkpoint reload must preserve the greedy policy used for validation.
