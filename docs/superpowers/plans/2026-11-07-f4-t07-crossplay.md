# F4-T07 Cross-play Matrix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Regenerate the EXP-I2 8×8 attacker–defender cross-play matrix for all three EXP-I1 pool seeds from their checkpoints.

**Architecture:** Validate sibling pool checkpoint runs from one `RUN` path, evaluate each pair through the fixed attacker suite, cache every cell with weight hashes, then aggregate seed ERs and plot the matrix.

**Tech Stack:** Python, Gymnasium, PyTorch, Docker lab, Matplotlib, pytest.

**Spec:** `docs/superpowers/specs/2026-11-07-f4-t07-crossplay-design.md`

## Global constraints

- EXP-I2 uses `attacker-eval-v1` on `test` with 200 episodes and query budget 50; evaluations never update policies.
- Exactly pool seeds 0–2 and generations 1–8 from one EXP-I1 training SHA; do not silently skip missing cells.
- Preserve source run ID and SHA, evaluation run ID and SHA, seed, generations, suite, and checkpoint weight hashes.
- The heatmap uses the mean of three seed ER values per cell; IC is over seeds, never episodes.

## Review focus

- Reject mismatched roles, seed, generation, training SHA, and checkpoint files before evaluation.
- Reject stale or malformed cached cells, including wrong weight hashes and episode budgets.
- Do not mix attacker and defender checkpoints across seeds or conditions.
- A rerun must produce byte-identical summaries and must not modify checkpoints.
- Keep `test` results out of model selection for F4-T08.
